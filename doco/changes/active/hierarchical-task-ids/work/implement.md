# 实施设计

## 1. 现状、目标与设计基线

[src/check/tasks.rs](../../../../../src/check/tasks.rs) 用正则同时识别任务行和依赖 ID，目前只接受 `T` 加至少三位数字。[assets/skill](../../../../../assets/skill/) 是安装源，[仓库内 doco skill](../../../../../.agents/skills/doco/) 是安装副本；[文档格式](../../../../../docs/document-format.md) 定义公开格式。测试夹具和仓库自己的 active/completed 工作包仍使用旧编号。当前未提交的 list 与终端改动不改变任务 ID 的解析职责，本变更不得覆盖这些工作。

## 2. 整体方案

在任务解析器中将任务行与依赖校验统一切换为两级正整数格式，并更新诊断示例。同步修改格式文档、create 指引、两份任务模板、测试夹具和仓库工作包，使新建项目、仓库内 Agent 指引、机械检查和现有数据使用同一格式。任务计数继续复用同一解析结果，无需修改生命周期或渲染层。

## 3. 关键 API 与数据模型

`Task.id: String`、`Task.dependencies: Vec<String>` 和 `parse(&str) -> Tasks` 签名不变，ID 仍作为不透明字符串参与唯一性、依赖查找和环检测。合法语法固定为 `[1-9][0-9]*\.[1-9][0-9]*`；`0.1`、`1.0`、`01.1`、`1.01`、单级数字、三级数字和旧 `T` 编号均非法。无状态、持久化、并发或生命周期 API 变化。

## 4. 核心算法与实现规则

任务行正则捕获 checkbox、分层 ID 和动作文本；依赖字段继续按空白、逗号、中文逗号或顿号拆分，再以相同 ID 正则逐项校验。后续 BTreeMap 唯一性检查和 Kahn 环检测保持原样。编号只表达人工分组，不检查连续性、排序或父级任务是否存在。仓库迁移按各工作包原有阶段分组重编号，并同步任务行、依赖与验证记录中的引用；围栏和注释示例也改为新格式，但仍由 Markdown 过滤器忽略。

## 5. 固定决策与可自主调整范围

固定决策是只接受恰好两级、无前导零的正整数编号，并完全拒绝旧格式；不增加兼容开关、迁移命令或隐式转换。编号可不连续，主次编号的具体分组由任务作者决定。实施可局部提取正则常量或测试辅助，但不得放宽语法或改变既有依赖语义。未决问题：无。

## 6. 验证与长期文档影响

自动测试覆盖合法分层编号、重复、未知依赖、依赖环、未完成依赖及多种非法边界，并确认围栏、注释和 list 计数行为。运行 fmt、clippy、全部目标测试、locked release 构建和 Rust 1.85 locked 检查；扫描项目源码与文档，确认不再残留旧任务编号。更新 [文档格式](../../../../../docs/document-format.md) 的当前格式契约和 skill 的 create/template 文件；架构边界未改变，无需 ADR 或架构文档更新。
