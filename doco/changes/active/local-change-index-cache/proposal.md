# 本地变更目录索引缓存

## 目的

降低变更数量增长后 `doco new` 等命令的目录扫描开销。当前 `new` 为检查单个 ID，调用 Project::changes() 遍历 active、completed、archived 的全部条目，并对每个路径从盘符开始重复检查父目录。此前在本机 G 盘使用已安装 release 二进制进行临时项目对照测试，每档三次：0、100、1,000、5,000、10,000 个既有变更时，创建完整包的中位耗时分别为 0.075s、0.152s、0.752s、3.554s、6.536s。夹具只建立状态下的变更目录，用于隔离索引扫描成本；这确认了规模增长点，但没有确定用户观察到的一次 30.3s 调用的全部原因。

引入只在本机保存、可随时删除重建的 CSV 索引，缓存 ID 与生命周期状态。工作包目录继续是事实来源，缓存不是文档内容、完成检查结果或实现历史。初始化时明确显示正在建立缓存，使从远端拉取项目后的准备过程可见；提供 `doco fix` 强制重建。

## 范围与完成标准

- 缓存位于 doco/tmp/changes-index.csv，采用固定三列 `type,key,value`，包含格式版本、写入日期时间、三个状态目录的精确 mtime 和 ID → 状态。默认利用现有 tmp 目录忽略规则，不提交 Git，不作为跨机器共享文件、skill 模板或发布包资源。工具不执行 Git 命令，也不擅自修改既有用户忽略规则。
- 目录 mtime 与缓存保存的值逐项相等才允许命中；缓存生成日期只用于排查，不作为新旧判定。缓存缺失、格式损坏、未知版本或目录 mtime 不匹配时回退权威目录扫描。路径不安全、实际目录非法或重复 ID 仍明确报错。
- Project::changes() 和目标解析接入缓存；读取指定 ID 或执行生命周期操作前仍直接核对三个状态目录中的同名路径，拒绝重复 ID、错误源状态、不安全路径和已存在目标。缓存不能替代原有目标内容、链接、快照及完成预检。
- `new`、`complete`、`archive`、`reopen`、`cancel` 在现有项目写锁内复用索引，完成业务预检后删除旧缓存，在首次业务修改前确保缓存不存在；操作成功后更新内存记录和目录 mtime，整体原子重写 CSV。删除旧缓存失败时不修改业务文件；中途失败时留下无缓存状态；业务成功但缓存写入失败时保留实际成果，以警告说明并提示 `doco fix`。
- `init` 在集成安装成功后强制重建缓存，即使集成文件全部为 SKIP。扫描前输出并刷新 `INDEX Building change index cache...`，成功后输出各状态数量。缓存步骤失败时明确区分“安装已完成”和“缓存未建立”，保留安装成果并提示恢复命令。
- 新增 `doco fix`，在写锁内忽略并撤销旧缓存、扫描和验证生命周期目录、原子写入新缓存；不修正文档、移动目录、删除工作包或自动选择重复 ID。未初始化项目仍提示先执行 init。
- `fix --dry-run` 只扫描和报告，`init --dry-run` 只在计划中说明将重建缓存；二者不创建缓存、锁文件或目录。原有 archive/cancel dry-run 也不增添缓存写入。
- 旧项目不必先运行 fix：只读命令缺缓存时扫描到内存，成功的生命周期写命令自动建立缓存。只读命令不加写锁、不持久化缓存；连续只读调用可能重复扫描，直到 init、fix 或成功的生命周期写操作刷新缓存。
- Git 拉取、切分支或手动新增/移动/删除工作包通常改变对应状态目录 mtime，从而触发重新扫描；文档明确 mtime 相等不是内容证明，时间戳恢复或低精度场景仍由指定目标核对和强制 fix 提供有限恢复，不能宣称发现所有无关目录变化。
- 保持完整包与 proposal-only 生命周期、列表状态过滤及实时任务/修改时间语义。缓存不包含正文、任务计数、包模式或验证结果；archive 的全局保留文档链接扫描不在优化范围内。
- 完成缓存格式、失效、恢复、锁冲突、输出顺序、路径安全和生命周期回归测试；在 100、1,000、10,000 个变更上记录冷/热缓存与 fix 的 release 基准。热缓存 new 的历史目录枚举次数为零，历史目录逐项安全检查次数为零；CSV 文件整体读写和内存索引仍随条目数增长，不承诺严格 O(1)。
- 实现完成后同步当前架构、CLI 契约、新增缓存格式契约及 README 使用说明；本创建阶段只交付工作包，不把计划写成已实现事实。

非目标：数据库、后台监听器、dirty 标记、增量日志、逐行原地修改缓存、自动 Git 钩子、跨文件断电事务、任意外部并发写入下的强一致性、只读命令自动持久化缓存、加速归档全文引用检查、自动修复或迁移文档。

## 结果

已交付本机可丢弃的变更目录索引缓存 doco/tmp/changes-index.csv（受限 CSV v1，仅记录 ID、状态和三个状态目录的纳秒级修改时间），以及显式重建入口 `doco fix`。`Project::changes` 与 `Project::resolve` 在缓存命中时不再枚举历史目录；指定 ID 仍核对三个真实路径，不安全缓存对象、损坏格式与时间戳不匹配均回退权威扫描。`new`、`complete`、`reopen`、`archive`、`cancel` 在项目写锁内按“预检 → 撤销缓存 → 业务提交 → 原子发布”维护索引；`init` 在安装成功后强制重建并先输出并刷新 `INDEX Building change index cache...`。只读命令与所有 dry-run 不写缓存、不加写锁、不创建 tmp。

规模基准（release，tests/scale.rs，默认忽略、显式运行，沙箱在 C 盘临时目录）：10,000 条历史变更下冷 `new` 14.62s、热 `new` 154ms；同一夹具在 `target` 盘的对照为冷 8.00s、热 0.09s（与 0 变更时的 0.075s 基线基本持平）。热路径包含完整缓存的读取与重写，整体读写仍随条目数线性增长，未声称严格 O(1)；归档的 doco 全文引用扫描未在本次优化范围内。

验证：`cargo fmt --all --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test`（含新增 14 项集成测试与 3 项缓存单元测试，全绿）和 `cargo build --release --locked` 均通过；新增依赖 `time 0.3.45` 声明 MSRV 1.83，低于项目声明的 1.85，`cargo +1.85 build --locked` 已编译全部依赖（随后仅因本次变更前已有的 let-chains 用法报错，未在本变更范围内修改）；手工冒烟验证 init/fix 输出、克隆后无缓存仍可 list、外部移动被重新扫描。当前架构、CLI 契约、README 及新增的缓存格式规范已同步。
