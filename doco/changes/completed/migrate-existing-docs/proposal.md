# 为既有项目文档补充迁移指导

## 目的
当前随工具发布的 doco skill 只说明当前文档维护和创建、执行、完成、归档四类变更操作。`doco init` 会建立规范目录和空的架构入口，但 skill 没有指导 Agent 如何盘点已有 README、分层 docs、混合设计文档、ADR 或其他文档体系，也没有规定如何判断内容应合并到 architecture、specs、decisions、active change，还是继续留在原位置。这会导致按文件名机械搬运、把历史计划写成当前事实、丢失内容或产生两套权威文档。

## 范围与完成标准
在发布态 doco skill 中增加一份既有文档迁移指南，并从 `SKILL.md` 明确路由到该指南。指南应支持扁平文件、分层 docs、单文件混合内容、已有 ADR/设计体系和重复或过期文档，要求先盘点与核实、输出迁移设计并获得批准，再执行写入或删除。

迁移按内容职责而非原目录名映射：已实现的整体事实进入 `doco/architecture.md`，必须精确定义的当前契约进入 `doco/specs/`，具有长期解释价值的决定进入 `doco/decisions/`；经确认仍在推进的目标才按创建流程转为 active change。用户文档、教程、运维手册、贡献说明、许可证、变更日志、生成物和不能确认的历史材料不得被强制塞入 doco。旧文件只有在目标内容、链接和保留策略验证且用户明确批准后才删除或改为导航。

发布资源、Rust 内嵌文件清单和本仓库安装态 skill 必须同步；初始化测试应证明新增引用会安装到共享及 Claude skill 目录。实施中发现 Windows 检出会让内嵌 skill 使用 CRLF，而兼容性比较只规范化已安装内容，导致相同 bundle 被误报冲突；本次一并把生成内容纳入既有换行规范化并增加回归测试。本文档变更不新增 CLI 迁移命令，不自动迁移任何目标项目，不改变 doco 生命周期、机械文档格式或根入口协议。

完成标准为：全新安装的 skill 可发现迁移动作；迁移指南给出可复用的盘点表、语义映射、冲突与历史处理、审批门和验证闭环；现有初始化与生命周期测试继续通过；发布态和仓库安装态内容一致。

## 结果
已完成。新增英文既有文档迁移指南，覆盖盘点、按内容职责分类、事实核实、迁移设计审批、目标优先执行、旧文件处置和验证闭环，并接入发布态及安装态 skill。同步更新 Rust skill bundle，补充安装回归测试，并修复 LF/CRLF 导致 bundle 兼容性误报冲突的问题。`cargo test --all-targets`（65 项）、Clippy、格式检查、release 构建、diff 检查和 `doco check migrate-existing-docs` 均通过；未修改当前 architecture、spec 或 ADR。
