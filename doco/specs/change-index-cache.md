# 变更索引缓存格式

`doco/tmp/changes-index.csv` 是本机可丢弃的派生缓存，记录 `doco/changes/{active,completed,archived}` 直接子目录的 ID 与状态，避免每次查询都枚举全部变更。工作包目录始终是事实来源：缓存不含 proposal 正文、包模式、任务进度或验证结果，也不授予文件归属。

`doco/.gitignore` 默认忽略 `/tmp/`，缓存不进入版本控制。它只服务生成它的机器：目录修改时间是本机文件系统元数据，提交或复制到其他机器后不会匹配，只会触发重新扫描。

## 文件格式

受限三列 CSV，固定表头 `type,key,value`，UTF-8、LF、末尾换行：

```csv
type,key,value
meta,version,1
meta,updated_at,2026-09-14T10:00:00Z
directory,active,1789380000123456789
directory,completed,1789380000234567890
directory,archived,1789380000345678901
change,feature-a,active
change,feature-b,archived
```

- `meta,version` 固定一条，当前为 `1`；未知版本按缓存失效处理。
- `meta,updated_at` 固定一条，是写入时刻的 UTC RFC3339 秒级时间（`YYYY-MM-DDTHH:MM:SSZ`），只用于排查，不参与有效性判断。
- `directory,<state>` 三个状态各固定一条，值为该目录修改时间的 UNIX epoch 纳秒整数（十进制，可为负）。
- `change,<id>,<state>` 每个变更一条；`<id>` 必须满足 CLI 的 ID 规则，`<state>` 只能是 `active`、`completed` 或 `archived`。写出时按 ID 升序。
- 只支持上述固定形态：不接受 BOM、引号、转义、空行、注释、额外列，也不接受重复的元数据、目录或 ID 行。任何偏差都使缓存失效。

## 失效与恢复

读取时先取三个状态目录的修改时间，再安全读取并解析缓存，然后再次取这三个目录的修改时间；只有两次时间戳与缓存记录逐项相等时才使用缓存。目录修改时间不可用时只返回内存扫描结果，不读取也不写入缓存。

缓存缺失、内容损坏、版本未知或时间戳不匹配时，命令回退到权威目录扫描，并保留原有检查：路径安全、ID 合法性、目录类型和跨状态 ID 唯一性。缓存路径本身是不安全对象（链接、reparse point、硬链接、目录冒充文件）或读取失败时明确报错，不覆盖、也不绕过检查。

修改时间相等只是失效启发式，不是内容一致的证明：时间戳被恢复、低精度文件系统或目录整体替换都可能漏判。因此：

- 指定 ID 的操作始终直接在三个状态目录中核对真实路径，拒绝重复 ID、错误源状态和已存在目标；缓存不能授权跳过这些检查。
- 使用缓存的批量查询可能漏列目录时间戳未变化的无关条目；`doco fix` 或下一次成功写入会重新校准。
- 缓存始终可以删除，删除后所有命令仍可工作；缺少缓存不是错误。

## 维护

`new`、`complete`、`reopen`、`archive`、`cancel` 在项目写锁内维护缓存：预检通过后、首次业务修改前删除缓存，操作成功并通过最终校验后按实际状态整体原子重写。业务失败或进程中断会留下无缓存状态，下次命令重新扫描，不保留可能失真的旧缓存。业务已提交但缓存写入失败时，命令不回滚业务，改为警告并提示 `doco fix`。

`init` 在集成安装成功后强制重建缓存，包括受管内容全部未变化的情况。`fix` 是显式重建入口，先撤销旧缓存再扫描。只读命令和所有 `--dry-run` 不写缓存、不加写锁、不创建 `doco/tmp`。
